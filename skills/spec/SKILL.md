## 読むもの
- `.soujo/`・`soujo`・git は作業中のプロジェクトのもの。このスキルの置き場所へ cd したり、そこのファイルを読んだりしない。
- 既存の `.soujo/SPEC.md`。埋まっている節は聞き直さない。
- 技術の候補を出すときだけ、リポジトリの設定ファイル（`package.json`・`go.mod`・`mix.exs` など）。

## やること
- 1メッセージに1問、最大7問。各問に番号付きの答え候補を付ける。技術スタックも質問して決め、既定値を持たない。
- 答えを得るたびに `SPEC.md` の該当節（目的・やらないこと・受け入れ基準・技術判断）へ書く。最後にまとめて書かない。
- 4節が埋まったら終える。`SPEC.md` は100行以内。

## soujo に頼むこと
- 最初に `soujo init`（`.soujo/` を作る。既存のファイルは上書きしない）。
- 書き終えたら `soujo next set --layer plan --premise "SPEC.md 完成" --check "PLAN.md に層と完了条件が並ぶ" --effort high`。

## 出力の形
- 質問中は、1問と番号付きの候補の短い表だけ。
- 終わりに `SPEC.md` の骨組みを表1つ（節 / 要点）で示す。
