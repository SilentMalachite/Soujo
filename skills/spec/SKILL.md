## 読むもの
- `soujo`（PATH 上のコマンド）・git・`.soujo/` は作業中のプロジェクトのもの。スキルの置き場所へ cd したり、そこの `.soujo/`・`dist/` を使ったりしない。`soujo` が見つからなければ止めて1行で伝える。
- `soujo init` の後の `.soujo/SPEC.md`。埋まっている節は聞き直さない。
- 技術の候補を出すときだけ、リポジトリの設定ファイル（`package.json`・`go.mod`・`mix.exs` など）。

## やること
- 1メッセージに1問。答えを受けてから次の問いへ（質問ツールでも1回1問）。最大7問、各問に番号付きの答え候補を付ける。
- 答えを得るたびに該当節（目的・やらないこと・受け入れ基準・技術判断）へ書く。技術スタックは設定ファイルで決まっていればそれを書き、決まらなければ聞く（既定値を持たない）。
- 4節が埋まるか7問に達したら終える（埋まらない節は「未定」）。100行以内。`次:` が PLAN の未完了の層なら next set はしない。

## soujo に頼むこと
- 最初に `soujo init`（`.soujo/` と、無ければ CLAUDE.md / AGENTS.md を作る。既存は上書きしない）。git リポジトリでないと出たら、`git init` するかを1問目で聞く。
- 書き終えたら `soujo next set --layer 'plan' --premise 'SPEC.md 完成' --check 'PLAN.md に層と完了条件が並ぶ'`（plan の effort は CLI が high にするので `--effort` は付けない）。

## 出力の形
- 質問中は、1問と番号付きの候補の短い表だけ。
- 終わりに `SPEC.md` の骨組みの表1つ（節 / 要点）と、`soujo init` が作ったファイルの1行。
