# CLAUDE.md（Opus 5 版）

Claude Code でこのリポジトリを扱うときの指示。
Codex 用の `AGENTS.md` は**写しではない**（GPT-6 Astra 向けに文面が違う）。規約を変えるときは両方を直す。

## 1. 相手について（ユーザー）

- 一度に多くのことを頭に保持するのが苦手。**状態・手順・決定は会話ではなくファイルに置く。**
- 構造・対比・図・類比で理解するのが得意。文章の理解力は高いので、言葉を易しくする必要はない。**短く、密度高く。**
- 会話は日本語。コード・識別子・コミットメッセージは英語。
- セッションは体調により予告なく中断される。**いつ止まっても再開できる状態を常に保つ。**
- 音声には頼らない。長い縦スクロールも避ける（1応答は画面1枚を目安に）。

## 2. 応答の形（最重要）

- **質問は1メッセージに1つ。** 選択肢があるなら番号付きの短い表にする。
- **結論 → 根拠 → 詳細** の順。最初の1文が「何が起きたか／何が分かったか」に答える。
- 前置き、免責、繰り返しの要約、褒め言葉は書かない。同じ内容を2度書かない。
- 説明は**構造から**入る：比較表、依存図、Before/After、既知のものとの類比。細部はその後。
- 図は ASCII か Mermaid。色や動きに意味を持たせない（ダークモード前提）。
- 進捗報告：最初のツール呼び出し前に1文、途中は方針が変わったときだけ、終わりに結果1文＋変更ファイル一覧。

## 3. 作業の進め方（Opus 5 向け）

- 着手前に `.soujo/NEXT.md` と `.soujo/SPEC.md` を読む。仕様が揃っていれば**途中で確認を挟まず最後まで完了する。**
- **頼まれた範囲で完了する。** 範囲を広げない・狭めない・別物にしない。より良い案があれば1文で述べ、頼まれた通りに続ける。
- 判断が分かれ、結果が大きく変わる場合だけ確認する。それ以外は自分で決めて進める。
- 自分の検証はいつも通りでよい。**追加の検証ステップやサブエージェントによる再確認は行わない。**
- サブエージェントは `review` スキルの reviewer 1体だけ。他の作業は自分でやる。
- 以前の発言の訂正は、ユーザーのコードや判断が変わるときだけ短く告げる。それ以外は黙って直す。
- レビューを頼まれたら**見つけたものは全部報告する。** 重要度の絞り込みはユーザーが別途行う。

## 4. 区切りと再開の約束（`soujo` CLI が実務を担う）

- 作業単位は「層（layer）」＝ `.soujo/PLAN.md` の1チェック項目。1層は30分以内。
- **1層 = 1コミット。** テストが通らない状態で `layer done` しない。層の途中で止まるときは `soujo close`（WIP コミット）。
- 層を終える手順は固定（途中で失敗したら、失敗したコマンドから再実行する）：
  1. 最後の層だけ、先に節目を残す：`soujo log add '節目' --line '<何が終わったか>' --line '<何が未決か>'`
  2. 次の層の `NEXT.md` を書く：`soujo next set --layer ... --premise ... --check ... [--caution ...] [--effort ...]`（`--effort` は PLAN の層にだけ付ける。`spec` / `plan` は CLI が high にする）
  3. 締める：`soujo layer done "<層名>" --note "<1〜3行>"`（PLAN チェック → LOG 追記 → コミットまで一括）
- 中断の恐れが出たら、止まる前に `soujo close --note "<一言>"`。
- 節目は、SPEC を書き終えたとき・PLAN に層を足したときにも手順 1 と同じコマンドで残す。PLAN の層名を `節目` にしない（LOG の節目と衝突するので CLI が拒否する）。
- 次の一手の根拠は `soujo resume` の4行だけ。会話履歴に依存しない。
- `再開:` の行が `日ぶり: 先に soujo brief` で終わるときだけ、`soujo brief` の5行（進捗・以後・節目・空白・次）で現在地を掴む。resume スキルは4行の後にその5行を出す。go スキルの中では走らせない。
- 手順・状態・決定を会話の中だけに残さない。`.soujo/` に書く。

## 5. 書く文書の長さ

- ファイルに書く文書（SPEC、PLAN、README、記事草稿）は必要な中身だけ。埋め草の節、重複する要約、定型文を入れない。
- `NEXT.md` は5行以内、`LOG.md` の1エントリは3行以内、`PLAN.md` の1項目は1行（層名 — 完了条件）。上限は CLI が検証する。

## 6. 技術スタック

- 言語・フレームワーク・テスト方法は決めつけない。`.soujo/SPEC.md` の「技術判断」に書かれたものに従う。書かれていなければ、リポジトリにある設定ファイル（`mix.exs` / `gleam.toml` / `go.mod` / `*.csproj` / `package.json` など）から読み取り、それでも不明なら1問だけ聞く。
- 既存のリポジトリでは、そこにある慣習（フォーマッタ、テストランナー、ディレクトリ構成）を優先する。新しい流儀を持ち込まない。
- 依存追加は、追加前に「何のために・代替は何か」を1行で示す。
- 秘匿情報（トークン・認証ファイル・Claude や Codex のセッション URL、個人情報・ホームディレクトリの絶対パス、業務記録の実データ）をコード・ログ・コミットメッセージに含めない。

## 7. やらないこと

- 会話の中だけに存在する手順や状態を作らない。
- ユーザーに「前回何を話したか」を思い出させる質問をしない。`soujo resume` を使う。
- 一度に複数の質問、長い選択肢、長い前置き。
- `AGENTS.md` を CLAUDE.md からコピーして上書きしない（文面が違うのは意図的）。
