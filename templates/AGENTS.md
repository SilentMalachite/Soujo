# AGENTS.md（GPT-6 Astra 版）

Codex でこのリポジトリを扱うときの指示。
Claude Code 用の `CLAUDE.md` より短いのは意図的（Astra は指示が多いほど文脈を浪費し、止まりやすくなる）。

## 相手

- 状態・手順・決定は会話ではなく `.soujo/` に置く。相手は会話を覚えていない前提で動く。
- 説明は表・図・対比から。言葉は普通の専門語でよい。短く。
- 日本語で応答。コード・識別子・コミットメッセージは英語。
- セッションは予告なく途切れる。止まる前に `soujo close`。

## 応答の形

- 質問は1つずつ。番号付きの選択肢を添える。
- 最初の1文で結果を言う。前置き・免責・繰り返しの要約は不要。
- 終わりに結果1文＋変更ファイル一覧。

## 許可と完了

- このリポジトリでの実装・テスト・コミットは許可済み。確認を待つのは、読み方によって成果物が大きく変わるときだけ。その場合も質問を投げつつ、依存しない部分は続けてよい。
- 「完了」の定義は `.soujo/PLAN.md` の該当層の完了条件。**最初の実装で戻ってこず、完了条件を満たすまで続ける。** 満たしたら `soujo next set` → `soujo layer done` で締める（最後の層は `next set` の前に節目を残し、`次:` を `converge` にして、締めたら `$converge`）。
- `.soujo/SPEC.md` の `## 原則` は、SPEC のほかの節・PLAN の完了条件・既存のコードより優先する。原則を守ると完了条件を満たせないときは、その食い違いを1問聞いてよい（依存しない部分は続けてよい）。
- 頼まれた層の範囲で終える。別案があれば1文で述べ、頼まれた通りに進める。
- レビューを頼まれたら見つけたものを全部、表で出す。絞り込みはこちらでやる。

## 記録（`soujo` CLI）

- 再開：`soujo resume`。`再開:` の行が `日ぶり: 先に soujo brief` で終わるときだけ、続けて `soujo brief`（`$resume` は両方を返す。`$go` の中では走らせない）。層を締める：`soujo next set ...` のあと `soujo layer done '<層名>' --note '...'`。中断：`soujo close --note '...'`。
- 節目：SPEC を書き終えたとき・PLAN に層を足したとき・converge を終えたとき・最後の層を `layer done` する前（`next set` より先）に `soujo log add '節目' --line '<終わったこと>' --line '<未決>'`。途中で失敗したら失敗したコマンドから再実行する。PLAN の層名を `節目` にしない（CLI が拒否する）。
- `layer done` / `close` がサンドボックスで git に書けず失敗したら、権限の昇格を求めて同じコマンドを再実行してよい（記録は重複せず、コミットだけやり直る）。
- `NEXT.md` は5行、`LOG.md` の1エントリは3行。上限は CLI が検証する。

## スタック

- 言語・フレームワークは `.soujo/SPEC.md` の技術判断とリポジトリの設定ファイルから読み取る。決めつけない。既存の慣習を優先する。
- 秘匿情報（認証情報・セッション URL・個人情報・ホームディレクトリの絶対パス）をコード・ログ・コミットメッセージに含めない。
